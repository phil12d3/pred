simulate Documentation

Deterministic scenario generation for what-if analysis.

Start with examples/demo.ns and examples/scenario_sweep.ns.

What This Module Is For

simulate explores alternatives to the most recent state of a history. It does not sample random futures and it does not contain a physics or probability engine. Instead, it deterministically rewrites the last row of a history and generates one or more scenario variants.

This is the classic “what if we changed the latest condition?” workflow. For example: what if demand were 20 instead of 15, what if the device state were "active" instead of "idle", or what if both changed together?

The module treats the newest row as the point of intervention. Older rows remain unchanged. That means the scenario branch is local and easy to inspect.

Conceptual Model

Every scenario starts from an observed history. A change object such as {A: 10, B: "active"} acts like a counterfactual intervention on the most recent row. In causal language, you are not claiming that the world truly changed. You are asking what the downstream system would see if the latest state had been different.

The current implementation is deterministic and exhaustive. If you give it two axes such as A = [1, 2] and B = ["idle", "active"], it builds the full cross-product of combinations rather than sampling a subset.

Functions

applyChanges(row, changes)

Use it for: making a modified copy of a single row.
Input: a row object and a change object.
Output: a new row with the requested replacements applied.
row = {A: 3, B: "idle", C: 12}; changed = simulate.applyChanges(row, {B: "active", C: 15}); // changed = {A: 3, B: "active", C: 15}

This is a direct overwrite operation. Fields listed in changes replace the corresponding row values. Unmentioned fields are preserved.

withLastRow(history, changes)

Use it for: branching a history at its latest point.
Input: a history object and a change object.
Output: a new history where only the last row differs.
branch = simulate.withLastRow( { streamNames: ["A", "B"], rows: [{A: 1, B: "low"}, {A: 2, B: "mid"}] }, {B: "high"} ); // branch.rows = [ // {A: 1, B: "low"}, // {A: 2, B: "high"} // ]

This is the most important transformation in the module. It leaves history length and stream names unchanged. Only the newest observation is rewritten.

sweepLast(history, streamName, values)

Use it for: testing several possible values for one stream.
Input: a history, one stream name, and a list of values.
Output: an array of scenario histories.
scenarios = simulate.sweepLast(history, "A", [10, 20, 30]); // scenarios.count() = 3 // scenarios[0].rows[last].A = 10 // scenarios[1].rows[last].A = 20 // scenarios[2].rows[last].A = 30

This is a one-dimensional parameter sweep. It is useful when you want to inspect sensitivity to one variable while holding everything else constant.

scenarioChanges(changeMap)

Use it for: generating the full set of multi-axis change objects.
Input: an object such as {A:[1,2], B:["idle","active"]}.
Output: an array of change objects representing every combination.
variants = simulate.scenarioChanges({ A: [1, 2], B: ["idle", "active"] }); // variants = [ // {A: 1, B: "idle"}, // {A: 1, B: "active"}, // {A: 2, B: "idle"}, // {A: 2, B: "active"} // ]

This is a Cartesian product. In data theory, a Cartesian product enumerates every combination across independent option sets. That is why the number of scenarios grows quickly when many streams have many candidate values.

scenarioHistories(history, changeMap)

Use it for: applying the full scenario grid directly to a history.
Output: one history per scenario combination.

The function first builds the change combinations with scenarioChanges(), then applies each combination to the last row with withLastRow().

forecastScenarios(system, history, changeMap)

Use it for: packaging scenario histories together with the target system object for later forecasting steps.
Current output: rows of the form {changes, history, system}.
Despite its name, the current implementation does not call the prediction engine itself. It prepares scenario histories and pairs them with the provided system. The docs state this explicitly because the older summary implied that forecasts were already being computed.

historyFromRows(streamNames, rows)

Use it for: building a history object inside simulation workflows.
Output: {streamNames, rows}.

Example Scenario Flow

simulate = import("./simulate.ns").simulate; history = { streamNames: ["A", "B"], rows: [ {A: 1, B: "low"}, {A: 2, B: "mid"}, {A: 3, B: "mid"} ] }; variants = simulate.scenarioChanges({ A: [3, 5], B: ["mid", "high"] }); histories = simulate.scenarioHistories(history, { A: [3, 5], B: ["mid", "high"] });

The important data effect is this: the first two rows stay exactly the same in every branch. Only the final row changes, and it changes according to the generated scenario combination. That makes side-by-side comparison easy.

When To Use Which Function

  • Use applyChanges() when you only need a modified row.
  • Use withLastRow() when you want one counterfactual history.
  • Use sweepLast() when one stream is the only thing changing.
  • Use scenarioChanges() when you want the raw combination grid.
  • Use scenarioHistories() when you want ready-to-use history objects for each combination.
