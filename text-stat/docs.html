1) What text-stat Is For

The text-stat module gives you practical text analytics from raw text input, with a focus on clear, inspectable outputs rather than black-box model behavior. You can pass one string or a list of strings, then get back:

  • Word frequency counts
  • Top terms (leading words)
  • Rare terms (tail words)
  • Bigrams (adjacent two-word phrases)
  • Co-occurrence relationships within a context window
  • Neighbor words for a selected token
  • Word-form similarity scores
  • Stub/prefix groupings for related word families
  • A combined report object for dashboards and pipelines
  • Corpus-driven semantic relationships: hypernyms, hyponyms, peers, attributes, behaviors, connectors, clustering, and taxonomy
Important: The stats similarity function is spelling/form similarity only. For semantic relationships learned from meaning patterns in text, use the semantic namespace instead.

2) Import and Module Layout

The umbrella import file is text-stat.ns and exposes four namespaces:

  • tokenize
  • stats
  • utils
  • semantic
ts = import("./text-stat.ns"); // Examples: words = ts.tokenize.tokens("Alpha beta, beta."); report = ts.stats.report(["alpha beta", "beta gamma"]); corpus = ts.stats.from("Poodles are dogs. Dogs are animals."); rels = ts.semantic.relationships(corpus, "poodles", 5);

Namespace roles:

tokenize.*
Functions to normalize text and turn it into token arrays.
stats.*
Main analytics API. This is where most users spend their time.
utils.*
Shared helper functions used internally (sorting, numeric helpers).
semantic.*
Corpus-driven semantic learning. Discovers hypernyms, hyponyms, peers, attributes, behaviors, connectors, clusters, and taxonomy — all from pattern evidence in the text alone.

3) Data Model and Return Shapes

3.1 Corpus Object

Several stats functions accept a corpus object. A corpus is currently a simple object with one property:

{ docs: ["doc one text", "doc two text", ...] }

You usually create this with stats.from(...).

3.2 Common Row Shapes

ranked word row
{ word: string, count: number, ratio: number }
bigram row
{ pair: string, count: number }
neighbor row
{ word: string, count: number }
stub group row
{ group: string, total: number, words: [ {word, count}, ... ] }

3.3 Semantic Return Shapes

specificity row
{ word, specificity, numNeighbors, totalCooc, segmentRatio, balance, connectorLike }
relation row (hypernym/hyponym/peer)
{ word, score, specificity, overlap, direction }
attribute/behavior row
{ word, score }
connector row
{ word, score, hubRatio, segmentRatio, neighborCount }
relationships result
{ word, hypernyms, hyponyms, peers, attributes, behaviors, connectors, connectorNeighbors }
taxonomy result
{ generalToSpecific: [ {word, specificity}, ... ], wordCount }
cluster
An array of word strings grouped by co-occurrence similarity and shared relation type.

3.3 Full Report Shape

{ docs: number, tokens: number, uniqueWords: number, leadingWords: [ {word, count, ratio}, ... ], tailWords: [ {word, count, ratio}, ... ], bigrams: [ {pair, count}, ... ], coOccurrence: { tokenA: { tokenB: count, tokenC: count, ... }, tokenB: { tokenA: count, ... } }, groups: [ {group, total, words: [...]}, ... ] }

4) tokenize Functions

tokenize.normalize(text)

Purpose: Convert input to a predictable string.

Behavior:

  • Returns empty string for null/undefined input
  • Returns input directly when it is already a string
  • Uses stringify for non-string values
s = ts.tokenize.normalize(42); // "42" s2 = ts.tokenize.normalize(null); // "" s3 = ts.tokenize.normalize("Hello"); // "Hello"

tokenize.toLowerText(text)

Purpose: Lowercase text in a runtime-safe way.

When to use: Anytime you need case-insensitive matching before token-level operations.

low = ts.tokenize.toLowerText("Alert HIGH CPU"); // "alert high cpu"

tokenize.tokens(text)

Purpose: Split text into lowercase alphanumeric tokens.

Behavior details:

  • Punctuation is treated as a separator
  • Only letters and numbers are kept in tokens
  • Output is lowercase
tokens = ts.tokenize.tokens("CPU spike! CPU 95%, server-1 unstable"); // ["cpu", "spike", "cpu", "95", "server", "1", "unstable"]

tokenize.uniqueTokens(text)

Purpose: Return unique tokens only, first-seen order.

u = ts.tokenize.uniqueTokens("a a b c c b"); // ["a", "b", "c"]

tokenize.lines(text)

Purpose: Split text by newline.

rows = ts.tokenize.lines("line1\nline2\nline3"); // ["line1", "line2", "line3"]

5) stats Functions

stats.from(textOrList)

Purpose: Build a corpus object from one string or an array/list of strings.

c1 = ts.stats.from("single document"); c2 = ts.stats.from(["doc one", "doc two"]); // c2 shape: // { docs: ["doc one", "doc two"] }

stats.wordCounts(corpus)

Purpose: Count token usage across all corpus documents.

Returns: { counts: object, total: number }

c = ts.stats.from(["a b b", "b c"]); wc = ts.stats.wordCounts(c); // wc.total = 5 // wc.counts = {a:1, b:3, c:1}

stats.rankedWords(corpus)

Purpose: Convert raw counts into sorted rows with relative frequency ratio.

Returns: [ {word, count, ratio}, ... ] sorted by count descending.

rows = ts.stats.rankedWords(corpus); // Example row: {word:"error", count:12, ratio:0.18}

stats.leadingWords(corpus, n)

Purpose: Return top N frequent tokens.

Default n: 10

top10 = ts.stats.leadingWords(corpus); top5 = ts.stats.leadingWords(corpus, 5);

stats.tailWords(corpus, n)

Purpose: Return N least frequent tokens.

Default n: 10

Interpretation note: tail words are useful for anomaly review (rare terms, one-off IDs, or possible misspellings).

stats.bigrams(corpus)

Purpose: Count adjacent two-token phrases (token[i] + token[i+1]).

Returns: [ {pair, count}, ... ] sorted descending by count.

c = ts.stats.from(["service outage service outage"]); b = ts.stats.bigrams(c); // [{pair:"service outage", count:2}, {pair:"outage service", count:1}]

stats.bigramsFrom(textOrList)

Purpose: Convenience wrapper for text-in/list-in to bigram-list-out.

b = ts.stats.bigramsFrom([ "service outage detected", "service outage resolved" ]); printraw(b);

stats.coOccurrence(corpus, windowSize)

Purpose: Build token co-occurrence matrix using local context window.

Definition used: For each token at index i, all tokens in range [i-windowSize, i+windowSize] excluding i are counted.

Defaults: windowSize defaults to 2, minimum effective window is 1.

m = ts.stats.coOccurrence(corpus, 2); // Example access: // m["payment"]["retry"] => how often retry appears near payment

stats.neighbors(corpus, word, limit, windowSize)

Purpose: Get most common neighbors for one target token.

Returns: [ {word, count}, ... ] sorted descending.

Defaults: limit = 10, windowSize = 2

n = ts.stats.neighbors(corpus, "payment", 8, 2); for (i = 0; i < n.count(); i = i + 1) { printline(n[i].word, " -> ", n[i].count); }

stats.levenshteinDistance(a, b)

Purpose: Compute raw edit distance between two strings (insert/delete/replace cost 1).

d1 = ts.stats.levenshteinDistance("analysis", "analyst"); d2 = ts.stats.levenshteinDistance("abc", "xyz");

stats.similarity(a, b)

Purpose: Return normalized similarity score in range [0, 1].

Formula: score = 1 - distance / max(length(a), length(b)), then clamped to [0,1].

same = ts.stats.similarity("analysis", "analysis"); // 1 near = ts.stats.similarity("analysis", "analyst"); // e.g. 0.8 far = ts.stats.similarity("analysis", "banana"); // lower

stats.prefixGroups(corpus, prefixLen, minGroupSize)

Purpose: Group words by leading prefix "stub".

Defaults: prefixLen = 4, minGroupSize = 2

Returns: [ {group, total, words:[{word,count}, ...]}, ... ] sorted by total descending.

groups = ts.stats.prefixGroups(corpus, 4, 2); // Example group row: // { // group: "anal", // total: 12, // words: [ // {word:"analysis", count:5}, // {word:"analyst", count:3}, // ... // ] // }

stats.stubsFrom(textOrList, prefixLen, minGroupSize)

Purpose: Convenience wrapper for text/list input to stub-group list output.

stubs = ts.stats.stubsFrom([ "analysis analyst analytics analyze", "report reports reporting" ], 4, 2); printraw(stubs);

stats.report(textOrList, config)

Purpose: Build one consolidated report object with all core analytics sections.

Config properties:

topN
How many entries to include in leadingWords. Default 10.
tailN
How many entries to include in tailWords. Default 10.
windowSize
Context window size for coOccurrence. Default 2.
prefixLen
Stub length used for groups. Default 4.
report = ts.stats.report(docs, { topN: 12, tailN: 8, windowSize: 3, prefixLen: 5 }); printline("docs:", report.docs); printline("tokens:", report.tokens); printline("unique:", report.uniqueWords); printraw(report.leadingWords); printraw(report.bigrams); printraw(report.groups);

7) semantic Functions

The semantic namespace learns relationships directly from corpus structure. No LLMs, no hardcoded word lists, no external resources. All relationship evidence comes from repeated sentence patterns and co-occurrence statistics inside the text you provide.

How it works: The model splits text into sentence-like segments, builds segment-bounded co-occurrence, learns which tokens act as structural bridges (e.g. "are", "can"), extracts directed taxonomy edges from those bridges, and scores each relation type separately. Attributes and behaviors are separated from category relations so they don't pollute hypernym/hyponym output.

semantic.specificity(corpus, word)

Purpose: Score how general or specific a word is relative to the whole corpus.

Returns: A specificity row with specificity as the main signal. Higher score = more general/central. Lower score = more specific/peripheral.

corpus = ts.stats.from("Poodles are dogs. Dogs are animals."); spec = ts.semantic.specificity(corpus, "animals"); printline(spec.specificity); // higher than dogs, dogs higher than poodles

semantic.hypernyms(corpus, word, limit)

Purpose: Find parent concepts — words more general than the target that the corpus implies the target belongs to.

Default limit: 5

Returns: Array of relation rows sorted by score descending.

hyper = ts.semantic.hypernyms(corpus, "poodles", 3); // [{word:"dogs", score:1, ...}]
Implementation note: Uses learned taxonomy edges (e.g. "X are Y" patterns) as primary source. Falls back to specificity-gap scoring when direct edges are absent.

semantic.hyponyms(corpus, word, limit)

Purpose: Find child concepts — specific examples or subcategories the corpus places under the target.

Default limit: 5

hypo = ts.semantic.hyponyms(corpus, "dogs", 5); // [{word:"poodles",...}, {word:"bulldogs",...}, ...]

semantic.relationships(corpus, word, limit)

Purpose: Full relationship map for one word — the main entry point for semantic exploration.

Default limit: 3 per category

Returns: A relationships result object with these fields:

hypernyms
Parent category concepts. Direct parent/child terms excluded from peers.
hyponyms
Specific subcategories or examples.
peers
Sibling-like terms at similar specificity level that share a common parent.
attributes
Descriptive properties associated with the word via the dominant bridge (e.g. "loyal" for "dogs").
behaviors
Action-like associations learned from secondary bridge patterns (e.g. "run" for "dogs" via "can").
connectors
Global bridge token list for this corpus.
connectorNeighbors
Bridge tokens that appear locally near this specific word.
corpus = ts.stats.from(animalText); rels = ts.semantic.relationships(corpus, "dogs", 3); printline(rels.word); // "dogs" printline(rels.hypernyms[0].word);// "animals" printline(rels.hyponyms[0].word); // "poodles" printline(rels.peers[0].word); // "cats" printline(rels.attributes[0].word); // "loyal" printline(rels.behaviors[0].word); // "run"

semantic.connectors(corpus, limit)

Purpose: Return the corpus-derived bridge/function tokens — words that structurally connect concepts across many sentence patterns.

Default limit: 10

Returns: Array of connector rows sorted by score descending.

Interpretation: A token qualifies as a connector when it has both high hub ratio (connects many different neighbors) and high segment ratio (appears across many sentences). In most English corpora this captures copulas and modal verbs like "are", "is", and "can".
conn = ts.semantic.connectors(corpus, 5); // [{word:"are", score:0.83, ...}]

semantic.connectorNeighbors(corpus, word, limit)

Purpose: Return connector tokens that appear locally near a specific word.

Default limit: 10

cn = ts.semantic.connectorNeighbors(corpus, "dogs", 5); // [{word:"are", count:4}, {word:"can", count:1}]

semantic.semanticClusters(corpus)

Purpose: Group words into clusters based on co-occurrence similarity and shared relation type.

Returns: Array of clusters. Each cluster is an array of word strings.

Clustering behavior: Words are grouped first by relation role (category/attribute/behavior), then by contextual similarity within each role. This prevents action words and descriptor words from bleeding into taxonomy clusters.

clusters = ts.semantic.semanticClusters(corpus); i = 0; while (i < clusters.count()) { printline("Cluster {i+1}: {clusters[i].count()} words"); i = i + 1; }

semantic.taxonomy(corpus)

Purpose: Return all known words sorted from most general to most specific according to the learned taxonomy score.

Returns: { generalToSpecific: [...], wordCount: number }

Connector tokens are excluded from the ranking so bridge words do not dominate the top positions.

tax = ts.semantic.taxonomy(corpus); i = 0; while (i < 5 && i < tax.generalToSpecific.count()) { w = tax.generalToSpecific[i]; printline("{i+1}. {w.word} ({w.specificity})"); i = i + 1; } // 1. animals (16.58) // 2. dogs (10.75) // 3. cats (6.58)

8) End-to-End Usage Patterns

Pattern A: Direct convenience API (fastest path)

ts = import("./text-stat.ns"); text = [ "service outage detected", "service outage resolved" ]; bigrams = ts.stats.bigramsFrom(text); stubs = ts.stats.stubsFrom(text, 4, 2); report = ts.stats.report(text, {topN: 5, tailN: 5, windowSize: 2, prefixLen: 4});

Pattern B: Build once, analyze many ways

corpus = ts.stats.from(text); wc = ts.stats.wordCounts(corpus); ranked = ts.stats.rankedWords(corpus); neighbors = ts.stats.neighbors(corpus, "service", 10, 2); groups = ts.stats.prefixGroups(corpus, 4, 2);

Pattern C: Inspect then render

Use printraw during development for structure inspection, then build formatted output for end users.

rows = ts.stats.leadingWords(corpus, 10); printraw(rows); // development inspection for (i = 0; i < rows.count(); i = i + 1) { printline(rows[i].word, " -> ", rows[i].count); }

Pattern D: Semantic discovery from raw text

ts = import("./text-stat.ns"); text = " Poodles are dogs. Bulldogs are dogs. Dogs are animals. Cats are animals. Dogs are loyal. Dogs can run. "; corpus = ts.stats.from(text); // What category does "poodles" belong to? rels = ts.semantic.relationships(corpus, "poodles", 3); printline(rels.hypernyms[0].word); // "dogs" // What are the subcategories of "animals"? hypo = ts.semantic.hyponyms(corpus, "animals", 5); i = 0; while (i < hypo.count()) { printline(hypo[i].word); i = i + 1; } // What kind of concept is "dogs"? dogRels = ts.semantic.relationships(corpus, "dogs", 3); printline(dogRels.hypernyms[0].word); // "animals" printline(dogRels.attributes[0].word); // "loyal" printline(dogRels.behaviors[0].word); // "run"

9) Interpretation Notes and Caveats

Ties in frequency-based sorting

When counts tie, relative ordering may depend on the underlying sort behavior and insertion order. Do not assume a stable deterministic order among equal counts unless you add a tie-breaker rule yourself.

Prefix groups are heuristic

Prefix grouping does not perform linguistic stemming. It groups by literal leading characters. This is useful and fast, but it can merge unrelated words that happen to share a prefix, and split related words that do not.

Co-occurrence is context-window based

A larger window captures broader topical association, while a smaller window captures tighter local phrase association. Choose window size based on your analysis goal.

Tokenization is alphanumeric-focused

Punctuation is treated as separators and discarded. If you need punctuation-aware behavior (for example hashtags, emails, or programming symbols), you can extend tokenize.tokens logic.

Accented Latin characters (French, Spanish, German, etc.)

The tokenizer folds common accented characters to their ASCII base equivalent before tokenizing. For example, é → e, ü → u, ñ → n. This means café is tokenized as cafe and Éléphants as elephants. The trade-off is that accented and unaccented forms are merged, which is usually the desired behavior for frequency and relation analysis.

Note: French uses multi-word copulas like sont des ("are") rather than a single bridge word. The semantic module's bridge extractor works on single middle tokens, so French category sentences like "X sont des Y" may not produce clean taxonomy edges unless the corpus has sufficient repetition for the individual tokens to score as connectors.

Non-Latin scripts (Japanese, Chinese, Arabic, etc.)

The tokenizer and the ns runtime process strings as UTF-8 bytes. Characters outside the ASCII and Latin Extended ranges (such as CJK ideographs, Hiragana, Katakana, and Arabic) are not decoded to Unicode code points. This means multiple different characters can produce the same byte-level fragment token, making them indistinguishable to the semantic model. Full support for these scripts requires a Unicode code-point-aware runtime.

Similarity is form-based, not semantic

Normalized Levenshtein similarity measures character edit closeness. It is ideal for typo-like or inflection-like comparisons, but not a substitute for semantic embeddings or corpus-learned relations.

Semantic quality depends on corpus structure

The semantic module learns from repeated structural patterns in the text. A corpus with many consistent category sentences like "X are Y" produces clean taxonomy edges. Narrative or action-heavy text will produce weaker results. More repeated patterns of the same structure reliably improve output quality.

Mixing semantic domains

You can mix multiple topics in one corpus. The model will learn cross-domain structure, but global specificity scores and cluster membership will be influenced by whichever domain is more repetitive or structurally dominant. For high-precision taxonomy within a domain, keeping domains separate or roughly balanced by text volume is usually better.

Connector detection is threshold-based

A token qualifies as a connector when its hub ratio (how many different neighbors it has) and segment ratio (how many different sentences it appears in) both exceed corpus-relative thresholds. A token like "can" that appears in only a few sentences will show up as a connector neighbor for a specific word, but may not appear in the global connector list unless it appears frequently enough across the full corpus.

Peers are sibling-first, not similarity-first

Peers are found by looking for words that share at least one learned parent node in the taxonomy graph, with contextual similarity as a secondary scoring factor. Direct hypernyms and hyponyms are always excluded from the peer list so a parent category is not mistaken for a sibling.
