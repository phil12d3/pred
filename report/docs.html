report Documentation

Build readable report objects and render them as plain text lines.

Start with examples/demo.ns.

What This Module Is For

report is the presentation layer for terminal-friendly analysis output. It does not create forecasts, detect drift, or measure model quality. It takes structured rows from other modules and arranges them into titled sections.

The design goal is simple and stable text. That matters when you want output that can be printed line by line, logged, copied into notes, or compared between runs.

A report in this module is data first, text second. You build a structured report object, then call render() to turn it into printable lines.

Report Shape

{ title: "Forecast Report", sections: [ { title: "Prediction Summary", rows: [...] }, { title: "Forecast Score", rows: [...] } ] }

This is a small document model. Each section has a title and a row array. Each row is an ordinary object. The rendering step turns each row into one text line by printing its scalar fields as name=value pairs.

Functions

create(title)

Use it for: starting an empty report.
Output: {title, sections: []}.

section(title, rows)

Use it for: building one section object explicitly.
Output: {title, rows}.

addSection(report, title, rows)

Use it for: appending a new section to an existing report.
Output: a new report object with one additional section.
r = report.create("Analysis Report"); r = report.addSection(r, "Summary", [{stream: "A", value: 10}]);

This keeps report assembly compositional. You can start with a title and add sections one by one as new outputs become available.

forecastReport(forecast, actualRow, streamNames)

Use it for: building a complete report around one forecast result.
Input: a forecast object, the actual row to compare against, and the stream order.
Output: a report titled "Forecast Report".

This function combines three pieces of information:

  • A prediction summary from explain.summarizePrediction().
  • A forecast score from eval.scoreForecast().
  • The forecast consistency rows already present in forecast.consistency.report.
r = report.forecastReport(forecast, actualRow, ["A", "B"]); // r.sections[0].title = "Prediction Summary" // r.sections[1].title = "Forecast Score" // r.sections[2].title = "Consistency"

driftReport(drift)

Use it for: building a report around a discrepancy drift object.
Output: a report titled "Drift Report" with one section called "Drift Summary".

Internally this uses explain.summarizeDrift() so the report contains flattened rows rather than raw nested drift objects.

evaluationReport(backtestResult)

Use it for: building a report from backtest metrics.
Output: a report titled "Evaluation Report".

This function uses eval.summarizeBacktest() to turn a stats object into a section called "Backtest Summary".

renderRow(row)

Use it for: converting one row object into one printable line.
Output: text such as stream="A" | value=10 | flagged=false.

Scalar values are printed directly. Arrays and nested objects are labeled as [array] or [object]. That behavior keeps rendered lines compact and avoids dumping deeply nested structures into the report body.

render(report)

Use it for: turning a whole report object into text lines.
Output: an array of strings ready to print.
lines = report.render(report.evaluationReport(backtest)); // lines[0] = "Evaluation Report" // lines[1] = "" // lines[2] = "Backtest Summary"

table(rows, config)

Use it for: rendering a plain row array as a bordered table.
Output: an array of strings containing a header row, separators, and one body row per input row.

The table renderer supports three border styles out of the box:

  • ascii uses + - | and stays safe for older terminals and logs.
  • box uses ┌ ┐ └ ┘ ─ │ ├ ┤ ┬ ┴ ┼.
  • double uses ╔ ╗ ╚ ╝ ═ ║ ╠ ╣ ╦ ╩ ╬.

You can also pass config.columns to fix the column order or override labels. Each entry may be a string column name or an object with name, label, and align fields.

Columns are detected from row object properties when you do not pass config.columns. Strings render as plain text, numbers right-align automatically, and arrays or nested objects render as [array] and [object].

lines = report.table([ {name: "Alpha", score: 12}, {name: "Beta", score: 3} ], {style: "box"}); // lines becomes a boxed table block.

renderTable(report, config)

Use it for: rendering a whole report with each section displayed as a table when possible.
Output: an array of strings with titles, section headers, and table blocks.

This is the report-level version of table(). It keeps the report title and section titles, then renders each section body as a table using the selected border style.

heatmap(grid, config)

Use it for: rendering numeric matrices as compact density maps.
Output: an array of strings, one per rendered row.

The heatmap helpers accept a two-dimensional array of numbers. Use width and height to resample the input to a new output size. Use scale: "auto" to derive the minimum and maximum from the rendered data, or pass scale: {min, max} to lock the range.

  • heatmapAscii(grid, config) uses a pure ASCII ramp.
  • heatmapBlocks(grid, config) uses ░ ▒ ▓ █.
  • heatmapColour(grid, config) uses full blocks plus foreground/background ANSI colour combinations.
  • heatmapLegend(bounds, config) renders a matching colour bar with min, midpoint, and max labels.

The coloured version is intended for terminal output via printline(). Its palette now fades across a wider ladder than the original stats tool by blending foreground and background ANSI colours across full block glyphs. The progression still starts in dark blue and ends in red, but it moves through more intermediate shades before reaching the top end.

heat = [ [0, 0, 1, 1], [0, 1, 2, 2], [1, 2, 3, 3], [2, 2, 3, 4] ]; ascii = report.heatmapAscii(heat, {width: 4, height: 4, scale: "auto"}); blocks = report.heatmapBlocks(heat, {width: 4, height: 4, scale: "auto"}); colour = report.heatmapColour(heat, {width: 4, height: 4, scale: "auto"}); legend = report.heatmapLegend({min: 0, max: 4}, {width: 32, style: "colour"});

How Rendering Changes The Data

The report object is structured data. The rendered output is a flat text representation of that structure. This distinction matters:

  • Before rendering, you can still add sections, inspect rows, or pass the object to another module.
  • After rendering, you have plain text lines intended for terminal or log output.

That separation follows a common software design rule: keep data structured as long as possible, then render at the boundary.

Example End-To-End Flow

report = import("./report.ns").report; evaluationLines = report.render( report.evaluationReport({ stats: { A: {type: "numeric", mae: 0.8, folds: 5}, B: {type: "categorical", accuracy: 0.6, folds: 5} } }) ); // evaluationLines becomes a printable text block.

The reporting module therefore serves as the last step after evaluation, explanation, or discrepancy analysis. It is less about mathematics and more about preserving meaning while changing representation.
