ingest Documentation

Turn raw records, columns, or single-series data into the row and history shapes used by the rest of the toolkit.

Start with examples/demo.ns and examples/records_to_history.ns. They show the same dataset being reorganized into toolkit-ready shapes.

What This Module Is For

ingest solves a structural problem, not a modeling problem. Real data arrives in different layouts. Forecasting code usually wants a stable time-ordered table: one row per time step and one named field per stream. This module converts several common layouts into that shape.

The underlying idea is simple data normalization. A later stage should not have to care whether the source was a list of records, a dictionary of columns, or a single list of values. Once the shape is normalized, downstream code can focus on feature extraction, prediction, discrepancy detection, or reporting.

A row is one observation such as {A: 3, B: "mid"}. A history is {streamNames, rows}, where streamNames preserves column order and rows stores the ordered observations.

Core Shapes

Shape Example What it means
records [{A:1, B:"low"}, {A:2, B:"mid"}] Already row-oriented. Each object is one event or time step.
columns {A:[1,2], B:["low","mid"]} Column-oriented. Useful when data was collected per field.
series [10, 12, 15] A one-dimensional stream that still needs a field name.
history {streamNames:["A","B"], rows:[...]} The normalized form expected by sibling packages.

How The Transform Works

All functions in this module preserve order. That matters because later prediction modules interpret the row order as time order. The first row is the oldest observation. The last row is the newest observation.

When a value is missing during conversion, null is inserted. This is deliberate. It keeps the table rectangular, which means every row has the same fields even if the source data was uneven.

records = [ {A: 1, B: "low"}, {A: 2}, {A: 3, B: "high"} ]; normalized = ingest.rowsFromRecords(records); // Result: // { // streamNames: ["A", "B"], // rows: [ // {A: 1, B: "low"}, // {A: 2, B: null}, // {A: 3, B: "high"} // ] // }

This is a common data engineering pattern. Rather than dropping incomplete observations or guessing replacements, the module keeps positional integrity and makes missingness explicit.

Functions

inferStreamNames(records)

Use it for: discovering the field order from record-style input.
Input: an array of objects.
Output: an array such as ["A", "B", "C"].
What it does: reads the first record only and returns its property names in that order.
names = ingest.inferStreamNames([ {A: 1, B: "low", C: 10}, {A: 2, B: "mid", C: 12} ]); // names = ["A", "B", "C"]

This function does not inspect later rows for extra fields. That means the first record defines the schema. For beginner use, that is predictable and easy to reason about, but it also means you should make sure the first record is representative.

rowsFromRecords(records)

Use it for: turning record-style data into the module’s normalized row bundle.
Input: an array of objects.
Output: {streamNames, rows}.
What it does: infers the stream names, then rewrites every record so each row has the same fields in the same schema.
normalized = ingest.rowsFromRecords([ {temp: 18, state: "idle"}, {temp: 21, state: "active"} ]); // normalized.streamNames = ["temp", "state"] // normalized.rows[0] = {temp: 18, state: "idle"}

The important effect is schema alignment. If one row is missing a field, the field still exists in the output row and is set to null. This helps later code compare rows field by field.

rowsFromColumns(columns)

Use it for: converting column-oriented data into row-oriented data.
Input: an object whose values are arrays.
Output: {streamNames, rows}.
What it does: computes the longest column length, then builds one row per index.
normalized = ingest.rowsFromColumns({ A: [1, 2, 3], B: ["low", "mid"], C: [10, 12, 15] }); // normalized.rows[1] = {A: 2, B: "mid", C: 12} // normalized.rows[2] = {A: 3, B: null, C: 15}

This function is effectively a column-to-row transpose. In data theory terms, it converts a field-major representation into an observation-major representation.

rowsFromSeries(streamName, values)

Use it for: wrapping a single numeric or categorical series in row form.
Input: a stream name and an array of values.
Output: {streamNames:[streamName], rows:[...]}.
What it does: creates one-field rows such as {sales: 10}, {sales: 12}, and so on.
single = ingest.rowsFromSeries("sales", [10, 12, 15]); // single.rows = [ // {sales: 10}, // {sales: 12}, // {sales: 15} // ]

This is useful when you want to start simple with one stream and later feed that result into a package that expects multi-stream history objects.

historyFromRows(streamNames, rows)

Use it for: wrapping already-normalized rows into a history object.
Input: a name array and a row array.
Output: {streamNames, rows}.
What it does: copies the arrays into the standard history shape used by the toolkit.

This is mostly a boundary function. It says, “this data is now ready to be treated as a time-ordered history.”

historyFromRecords(records)

Use it for: going directly from raw records to a history object in one call.
Input: an array of record objects.
Output: a history object.
What it does: runs rowsFromRecords() and then historyFromRows().

historyFromColumns(columns)

Use it for: going directly from column arrays to a history object.
Input: a column object.
Output: a history object.
What it does: runs rowsFromColumns() and then wraps the result as history.

windowRows(rows, maxRows)

Use it for: keeping only the newest rows.
Input: a row array and a maximum length.
Output: a shortened row array.
What it does: drops the oldest rows if the array is longer than maxRows.
recent = ingest.windowRows([ {A: 1}, {A: 2}, {A: 3}, {A: 4} ], 2); // recent = [{A: 3}, {A: 4}]

This is a rolling-window operation. In time-series work, a rolling window limits memory and focuses analysis on recent behavior.

windowHistory(history, maxRows)

Use it for: shortening a whole history object while keeping stream names intact.
Input: a history object and a maximum row count.
Output: a new history object with fewer rows.
What it does: keeps the schema, copies the newest rows, and discards older history beyond the requested depth.

End-To-End Example

ingest = import("./ingest.ns").ingest; records = [ {A: 1, B: "low", C: 10}, {A: 2, B: "low", C: 12}, {A: 3, B: "mid", C: 15}, {A: 4, B: "mid", C: 18} ]; normalized = ingest.rowsFromRecords(records); history = ingest.historyFromRecords(records); tail = ingest.windowHistory(history, 2); // normalized.streamNames = ["A", "B", "C"] // history.rows.count() = 4 // tail.rows = [ // {A: 3, B: "mid", C: 15}, // {A: 4, B: "mid", C: 18} // ]

The structural effect is clear. The raw data starts as records, becomes a standardized table, and can then be reduced to a recent window without changing its schema. That is exactly the kind of stable preprocessing other modules depend on.

When To Use Which Function

If your data looks like... Use... Why
[{...}, {...}] rowsFromRecords() or historyFromRecords() Your data is already row-oriented.
{A:[...], B:[...]} rowsFromColumns() or historyFromColumns() You need to transpose columns into rows.
[10, 12, 15] rowsFromSeries() You only have one stream and need a name for it.
Too much old data windowRows() or windowHistory() You want a recent rolling slice.
