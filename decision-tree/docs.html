Decision Tree Framework

A complete ns library for predictions on tabular data, text, vectors, and multi-stream systems. No external dependencies — pure decision trees with CART algorithm.

Quick Start Modules Configuration Return Values Examples Patterns

Quick Start

Import the library and train your first model in 5 lines:

dt = import("./des-tree.ns"); rows = [{features: {x: 1, y: 2}, target: "A"}, {features: {x: 5, y: 6}, target: "B"}]; model = dt.tabular.train(rows); result = dt.tabular.predict(model, {x: 1.2, y: 2.1}); printline(result.value); // → "A"

That's it. The model trained, predicted, and returned the most likely class.

Tip: Each row has target (what to predict) and features (inputs). The framework auto-detects whether you're doing classification (text targets) or regression (numeric targets).

Five Modules

dt.tabular

Mixed numeric and categorical features. Auto label-encodes categories.

Use when: Your data is a flat table with column values.

dt.text

String classification. Tokenizes, builds vocabulary, bag-of-words features.

Use when: Classifying short texts or documents.

dt.vectors

Dense numeric arrays (embeddings, sensor readings). Maps dimensions to features.

Use when: Input is a fixed-size numeric array.

dt.streams

Multi-stream mutual prediction. Each stream predicts all others.

Use when: Variables depend on each other (weather: temp ↔ humidity).

dt.evaluate

Metrics and cross-validation. Accuracy, MAE, RMSE, confusion matrices.

Use when: Measuring model quality.

dt.tree

Low-level CART engine. Impurity metrics, feature importance, node traversal.

Use when: Building custom prediction pipelines.

dt.tabular — Mixed Features

Train and predict on rows with numeric and categorical columns.

// Train system = dt.tabular.train(rows, config); // Predict single result = dt.tabular.predict(system, {age: 30, city: "NYC"}); // Predict batch results = dt.tabular.predictBatch(system, features_list); // Feature importance imp = dt.tabular.importance(system); // {age: 0.7, city: 0.3}
system.kind
string "classification" or "regression" — determined from your training targets.
result.value
any The predicted class (classification) or number (regression).
result.support
number 0–1 Fraction of training samples that ended at this leaf. Higher = more confident.
result.path
array Array of split decisions: [{feature: "age", threshold: 25, direction: "left", ...}, ...]
result.probabilities
object For classification: {label: probability} for each class.

Classify or analyze strings. Automatically tokenizes and builds vocabulary.

dt.streams — Multi-Stream Prediction

Train one model per variable; each predicts all others.

// Train system = dt.streams.train(["temp", "humidity", "rain"], rows); // rows = [{temp: 20, humidity: 70, rain: 0.5}, ...] // Predict specific stream result = dt.streams.predict(system, {temp: 22, humidity: 75}, "rain"); // Predict all streams at once all = dt.streams.predictAll(system, {temp: 22}); // uses default for humidity // Feature importance imp = dt.streams.importance(system, "rain"); allImp = dt.streams.allImportance(system);

dt.evaluate — Metrics & Cross-Validation

Measure accuracy, error, and model quality.

// Split data split = dt.evaluate.holdout(rows, 0.2); // 80/20 split // split.train, split.test // Per-sample results results = [{predicted: "A", actual: "A"}, ...]; acc = dt.evaluate.accuracy(results); mae = dt.evaluate.mae(results); // Cross-validation folds = dt.evaluate.kFold(rows, 5, train_fn, predict_fn); summary = dt.evaluate.summarizeKFold(folds);
split.train, split.test
array Original rows split into train and test.
accuracy, mae, rmse
number 0–1 (accuracy) or error value Accuracy ranges [0, 1]; MAE and RMSE are absolute or squared error.

Configuration: Controlling How the Tree Grows

Pass a config object to train() to customize tree depth and split behavior:

config = { maxDepth: 5, // Stop splitting at this depth minSamples: 3, // Don't split if fewer samples minGain: 0.0001 // Ignore splits with less gain }; model = dt.tabular.train(rows, config);
Parameter Type Default Effect
maxDepth number 6 Maximum tree depth. Deeper = more complex. Shallower = simpler, less overfitting.
minSamples number 2 Minimum samples required to make a split. Higher = smoother predictions, less noise.
minGain number 0.00001 Minimum information gain to accept a split. Higher = only strong splits used.
maxVocab (text only) number 500 Maximum vocabulary size. Lower = faster, fewer features.
minCount (text only) number 1 Minimum document frequency for a word to enter vocabulary.

Impact Examples

Conservative (avoid overfitting)
{maxDepth: 3, minSamples: 10, minGain: 0.001}

Result: Simple tree, smooth predictions, slower to train.

Aggressive (capture detail)
{maxDepth: 10, minSamples: 1, minGain: 0.0001}

Result: Deep tree, may overfit, very detailed decisions.

Balanced (default)
{maxDepth: 6, minSamples: 2, minGain: 0.00001}

Result: Reasonable complexity, generalizes well, good for most use cases.

Understanding Return Values

Every prediction returns a rich object with more than just the prediction:

result = dt.tabular.predict(model, {age: 30, income: 50000}); // result = { // value: "medium", // The prediction // support: 0.2, // 20% of training ended here // depth: 3, // Took 3 splits to get here // kind: "classification", // Task type // probabilities: { // For classification // "low": 0.1, // "medium": 0.8, // "high": 0.1 // }, // path: [ // How the tree decided // {feature: "income", threshold: 40000, direction: "right", gain: 0.15}, // {feature: "age", threshold: 25, direction: "right", gain: 0.10} // ] // }

Key Properties

value
any The main result. Class label or numeric prediction.
support
0 to 1 Confidence indicator. What fraction of training data reached this leaf? 0.5 = "half the training data was similar to this input."
depth
0 to maxDepth How many splits were needed. Shallow predictions (depth 1–2) are more general.
kind
"classification" or "regression" The task type — inferred from your training targets.
probabilities
object (classification only) Class probabilities: how likely each class is. Sums to 1.0. Missing classes have probability 0.
path
array of objects Explainability. Each step: {feature, threshold, direction, gain}. Shows exactly why the prediction was made.

Using the Path for Explainability

The path shows exactly which rules led to the prediction:

// Print a human-readable explanation result = dt.tabular.predict(model, features); printline("Predicted: ", result.value); for (i = 0; i < result.path.count(); i = i + 1) { step = result.path[i]; op = step.direction == "left" ? "<=" : ">"; printline(" ", step.feature, " ", op, " ", step.threshold); }

Output:

Predicted: high_risk age <= 30 income > 50000

This is your tree's logic for this prediction. Great for debugging and building trust.

Example: Multi-Stream Weather

Predict any weather variable from others:

// Train once with all streams system = dt.streams.train( ["temp", "humidity", "rain_chance", "wind"], observations ); // Know only temp and humidity → predict rain result = dt.streams.predict( system, {temp: 20, humidity: 80}, "rain_chance" ); printline("Rain chance: ", result.value); // Know only rain → predict everything all = dt.streams.predictAll(system, {rain_chance: 0.7}); printline("Expected temp: ", all.temp.value); printline("Expected humidity: ", all.humidity.value);

Common Patterns & Best Practices

Pattern 1: Classification with Confidence

Predict and filter by confidence
result = dt.tabular.predict(system, features); if (result.support > 0.3) { // High confidence: support > 30% of training use_prediction(result.value); } else { // Low confidence: ask user or use fallback ask_human_for_decision(); }

Pattern 2: Explainability

Show why a prediction was made
result = dt.tabular.predict(system, features); printline("Decision: ", result.value); printline("Why? "); for (i = 0; i < result.path.count(); i = i + 1) { s = result.path[i]; op = s.direction == "left" ? "<=" : ">"; val = features[s.feature]; printline(" Because ", s.feature, "=", val, " is ", op, " ", s.threshold); }

Pattern 3: Finding Important Features

What matters most?
imp = dt.tabular.importance(system); printline("Feature importance:"); foreach(f in imp.props) { printline(" ", f, ": ", imp[f]); }

Pattern 4: Train/Test Split

Evaluate generalization
split = dt.evaluate.holdout(all_rows, 0.2); system = dt.tabular.train(split.train); results = []; for (i = 0; i < split.test.count(); i = i + 1) { pred = dt.tabular.predict(system, split.test[i].features); results.add({ predicted: pred.value, actual: split.test[i].target }); } accuracy = dt.evaluate.accuracy(results); printline("Test accuracy: ", accuracy);

Pattern 5: Cross-Validation

Robust accuracy estimate (k-fold)
buildRows = func(raw) { result = []; for (i = 0; i < raw.count(); i = i + 1) { result.add({ features: raw[i].features, target: raw[i].target }); } return result; }; folds = dt.evaluate.kFold( buildRows(all_rows), 5, func(rows) => dt.tabular.train(rows), func(model, feat) => dt.tabular.predict(model, feat).value ); summary = dt.evaluate.summarizeKFold(folds); printline("Average accuracy: ", summary.accuracy);

Pattern 6: Reverse Prediction (Streams)

Use output as input
// One-shot: temp/humidity determine rain result1 = dt.streams.predict(system, {temp: 20, humidity: 75}, "rain"); // Reverse: rain determines temp/humidity result2 = dt.streams.predict(system, {rain: 0.8}, "temp"); result3 = dt.streams.predict(system, {rain: 0.8}, "humidity");

General Best Practices

  • Start simple: Use default config, then adjust if needed.
  • Guard splits: Always use holdout() or cross-validation before trusting accuracy.
  • Check support: Low support (< 0.1) means "not enough similar training data" — treat with caution.
  • Pair with probabilities: For classification, check result.probabilities to see how close the runner-up was.
  • Inspect the path: Paths let you debug unexpected predictions and build trust.
  • Use feature importance: It tells you what the model actually learned (useful for feature engineering).
⚠️ Remember: Decision trees are prone to overfitting with deep structures and small datasets. Always validate on held-out test data or use cross-validation. Increasing minSamples or lowering maxDepth helps prevent overfitting.

Deep Dives: Understanding Key Concepts

This section thoroughly explains the concepts mentioned throughout the docs so you truly understand what's happening.

Train/Test Splits & The Holdout Strategy

The problem: When you train a tree on some data and immediately test it on the same data, the accuracy will be misleadingly high. The tree has memorized patterns including noise.

Why it happens: Decision trees can grow arbitrary complex. With enough depth, a tree can perfectly classify training data — including the errors and flukes. This is called overfitting.

What holdout does: It separates your data into two parts: train (e.g., 80%) and test (e.g., 20%). The tree learns from train data, never seeing the test data. At the end, you measure accuracy only on test data.

// Example: 100 rows → 80 training, 20 test split = dt.evaluate.holdout(my_rows, 0.2); // Train on 80 system = dt.tabular.train(split.train); // Test on 20 (data the tree has never seen) results = []; for (i = 0; i < split.test.count(); i = i + 1) { pred = dt.tabular.predict(system, split.test[i].features); results.add({predicted: pred.value, actual: split.test[i].target}); } // This accuracy is realistic — not artificially inflated accuracy = dt.evaluate.accuracy(results);

Why it matters: This is your answer to "how good is my model, really?" If you test on training data, you're lying to yourself.

Rule of thumb: Always, always use a held-out test set before shipping a model.

Cross-Validation: Better Than Holdout

The problem with holdout: With only one 80/20 split, your test accuracy might be lucky or unlucky depending on which rows happened to be in the test set.

What k-fold does: It splits data into k equal parts ("folds"). It trains k times, each time using a different fold as test and the rest as train. Final accuracy is the average across all folds.

// Example: 5-fold cross-validation on 100 rows // Fold 1: train on rows 20-100, test on rows 0-19 // Fold 2: train on rows 0-19 + 40-100, test on rows 20-39 // ... etc ... // Final accuracy = average of 5 test accuracies folds = dt.evaluate.kFold( rows, 5, func(train_rows) => dt.tabular.train(train_rows), func(model, test_features) => dt.tabular.predict(model, test_features).value ); summary = dt.evaluate.summarizeKFold(folds); printline("Cross-validated accuracy: ", summary.accuracy);

Why it matters: You get 5 independent accuracy estimates instead of 1. More robust.

When to use:

  • Holdout: You have lots of data (1000+ rows) and a single 80/20 split is reliable.
  • k-fold: You have limited data (100–500 rows) and want a robust estimate.

Support: Measuring Confidence

What is it? The fraction of training samples that ended up at the same leaf node as your prediction.

result = dt.tabular.predict(system, features); printline("Support: ", result.support); // e.g., 0.15 = 15% of training

Interpretation:

  • support = 0.5 → Half of training data was similar to this input. Model is confident.
  • support = 0.1 → Only 10% of training was similar. Model is somewhat confident.
  • support = 0.01 → Only 1% of training was similar. Model is guessing in unfamiliar territory.

Why it matters: Low support predicts ions are more likely to be wrong. Use it to decide when to ask a human or reject the prediction.

result = dt.tabular.predict(system, features); if (result.support < 0.05) { printline("Low confidence (only 5% of training looks like this)."); printline("I suggest asking a human."); } else { printline("Prediction: ", result.value); }

Probabilities: Understanding Class Likelihood

What are they? For classification tasks, probabilities tell you the likelihood of each class at that leaf node.

result = dt.tabular.predict(system, my_features); // result.probabilities = { // "low": 0.1, // 10% of leaf samples are "low" // "medium": 0.8, // 80% of leaf samples are "medium" // "high": 0.1 // 10% of leaf samples are "high" // }

Why it matters: The top predicted class might be "medium" with 80%, but the runner-up is "high" with 10%. These are close! Use probabilities to decide how confident you are:

result = dt.tabular.predict(system, features); // Sort probabilities to find top 2 probs = []; foreach(label in result.probabilities.props) { probs.add({label: label, prob: result.probabilities[label]}); } probs = probs.sort(func(ai, av, bi, bv) => bv.prob - av.prob); top = probs[0]; runner_up = probs.count() > 1 ? probs[1] : null; margin = runner_up != null ? top.prob - runner_up.prob : top.prob; if (margin > 0.5) { printline("Very confident: ", top.label); } else if (margin > 0.2) { printline("Somewhat confident: ", top.label); } else { printline("Close call, could be either ", top.label, " or ", runner_up.label); }

Feature Importance: What the Model Learned

What is it? A score (0 to 1) for each feature, showing how much it contributed to the splits in the tree.

imp = dt.tabular.importance(system); // imp might be: // { age: 0.6, income: 0.3, debt: 0.1 } // Age drove most of the splits, income some, debt barely used.

Why it matters:

  • Debugging: If a feature you expected to be important isn't, maybe it's uncorrelated with the target.
  • Feature engineering: Features with low importance might be dropped to simplify the model.
  • Understanding the model: See what the model actually uses vs. what you assumed.

Interpretation:

  • score = 0.7 → This feature was responsible for 70% of the predictive power.
  • score = 0.01 → Almost unused — likely not important.

Overfitting: Why Deep Trees Fail

What is overfitting? The model learns the training data too well, including its noise and quirks. It fails on new data.

Decision trees and overfitting: Trees are particularly prone because they can grow infinitely deep and capture arbitrarily complex patterns.

Example:

// Overfitted tree: very deep, learns noise system1 = dt.tabular.train(rows, {maxDepth: 20, minSamples: 1}); train_acc1 = 0.99; // Perfect on training data! test_acc1 = 0.65; // Terrible on new data. Learned noise. // Well-tuned tree: stopped early system2 = dt.tabular.train(rows, {maxDepth: 5, minSamples: 10}); train_acc2 = 0.82; // Good but not perfect on training test_acc2 = 0.80; // Also good on new data. Learned patterns.

How to prevent it:

  • Reduce maxDepth: Shallow trees can't memorize noise.
  • Increase minSamples: Require more samples per leaf to make a split. Noise doesn't repeat consistently.
  • Use cross-validation: Detect if your tree is overfitting by comparing train vs. test accuracy.

Classification vs. Regression: Two Different Tasks

Classification: Predict a category or label.

rows = [ {features: {...}, target: "spam"}, {features: {...}, target: "legitimate"}, ... ]; // Target is one of a discrete set: "spam" or "legitimate" // Metric: accuracy (how many did we get right?)

Regression: Predict a numeric value.

rows = [ {features: {...}, target: 45.5}, {features: {...}, target: 62.3}, ... ]; // Target is a continuous number // Metric: MAE or RMSE (how far off were we on average?)

How the framework detects which: It looks at your targets. If they're all numbers, it's regression. Otherwise, classification.

Why it matters: Different metrics, different optimization. The configuration and interpretation change slightly.

Text Tokenization & Bag-of-Words

What happens when you train text:

// Input rows = [ {text: "Great product, highly recommend!", label: "positive"}, {text: "Terrible quality, don't buy", label: "negative"}, ... ]; // Step 1: Tokenize // "Great product, highly recommend!" → ["Great", "product", "highly", "recommend"] // Words are extracted (punctuation removed, case-insensitive) // Step 2: Build vocabulary // Collect all unique words from all training texts // Select top 500 by frequency // Step 3: Convert to features // Each text becomes a 500-dim binary vector: // feature[i] = 1 if word i is present, else 0 // "Great product" → [1, 1, 0, 0, ..., 0] (Great and product present) // Step 4: Train tree on these features // Tree learns rules like: if "great" present and "terrible" absent → positive

Why it works: Words are strong signals. A tree can learn to split on "scam"–present vs. absent, then on presence of money-related words, etc.

Limitation: Word order is lost. "This is good" and "This good is" both become the same feature vector.

Stream Defaults & Partial Predictions

What are stream defaults? When you train a multi-stream system, each stream learns a default value: the mean (numeric) or most common value (categorical).

system = dt.streams.train( ["temp", "humidity", "rain"], observations ); // During training, the system computes: // defaults.temp = average temperature across all observations // defaults.humidity = average humidity // defaults.rain = average rain_chance

Why: When you predict with missing values, the system needs something to put in for inputs you don't know. It uses the average from training.

// You know temp but not humidity result = dt.streams.predict(system, {temp: 25}, "rain"); // Internally: humidity is filled with its training mean // i.e., {temp: 25, humidity: 72.5} (if that was the average)

Why it matters: Predictions are only as good as their inputs. Missing values → less confident predictions. Use support to gauge this.

Information Gain & Tree Splits

The question every split answers: "Which feature and which threshold make the best cut?"

How the tree decides: It measures "impurity" before and after the split. Impurity is roughness — how mixed the classes are.

Before split: 50 samples, 30 class A, 20 class B → impure (mixed)

After split on feature X: Left: 40 samples, 35 class A, 5 class B (pure!); Right: 10 samples, 5 class A, 5 class B (very mixed)

Information gain: How much did we reduce impurity? Big reduction = good split. Small reduction = bad split.

The tree picks the highest-gain split.

Why it matters: You don't need to understand the math, but know that minGain lets you filter out weak splits:

// Only accept splits that improve at least this much {minGain: 0.0001} // Very permissive, many splits {minGain: 0.01} // More selective, only strong splits
