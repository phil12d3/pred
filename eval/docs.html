eval Documentation

Scoring utilities for forecasts, drift summaries, and backtest result comparison.

Start with examples/demo.ns and examples/forecast_score.ns.

What This Module Is For

eval measures output quality. It does not train models, engineer features, or detect drift by itself. Its job is to turn predictions and summary objects into explicit metrics so you can judge whether a result is good, bad, improving, or degrading.

In data science terms, this is the evaluation layer. You take an actual outcome and compare it with a predicted outcome, or you take two model runs and compare their metrics. The module keeps those comparisons beginner-friendly and flat.

A metric is just a rule for turning outcomes into a score. This module currently uses exact-match accuracy for categorical values and mean absolute error for numeric values.

Metric Concepts

Metric Meaning Why it matters
accuracy Fraction of correct comparisons. Easy to interpret for discrete labels and exact numeric matches.
numericMae Mean absolute error. Average size of the numeric miss. Shows how far numeric predictions are from reality without canceling positive and negative errors.
categoricalAccuracy Accuracy over non-numeric streams only. Keeps label performance separate from numeric performance.
delta Current metric minus baseline metric. Shows change between two backtest runs.

Mean absolute error is especially important. If the actual values are 9 and 4, and the model predicts 11 and 2, the absolute errors are 2 and 2. Their average is 2. Unlike signed error, MAE never hides mistakes by letting positive and negative misses cancel each other out.

Functions

scoreForecast(actualRow, forecastRow, streamNames)

Use it for: scoring one predicted row against one actual row.
Input: an actual row, a forecast row, and the ordered stream list.
Output: {comparisons, matches, accuracy, numericMae, numericCount, categoricalAccuracy, categoricalCount, byStream}.
score = evaluation.scoreForecast( {A: 9, B: "idle", C: 4}, {A: 11, B: "idle", C: 2}, ["A", "B", "C"] ); // score.comparisons = 3 // score.matches = 1 // score.accuracy = 0.333... // score.numericMae = 2 // score.byStream[0] = { // stream: "A", // kind: "numeric", // actual: 9, // predicted: 11, // match: false, // error: 2 // }

The scoring rule changes slightly by data type. If both values are numbers, the module computes absolute error and treats the prediction as an exact match only when that error is essentially zero. Otherwise it uses direct equality. This is a practical split between regression-style and classification-style evaluation.

compareForecasts(actualRow, forecastRow, streamNames)

Use it for: the same job as scoreForecast(), but with a name that reads more naturally in some scripts.
Current behavior: this is an alias for scoreForecast().

summarizeBacktest(backtestResult)

Use it for: flattening a backtest stats object into printable rows.
Input: a backtest object with a stats property keyed by stream.
Output: rows with stream, kind, metric, value, and folds.
backtest = { stats: { A: {type: "numeric", mae: 0.8, folds: 5}, B: {type: "categorical", accuracy: 0.6, folds: 5} } }; rows = evaluation.summarizeBacktest(backtest); // rows[0] = { // stream: "A", // kind: "numeric", // metric: "mae", // value: 0.8, // folds: 5 // }

This is a normalization step for reporting. Backtest outputs are usually keyed objects. Reports are easier to build from row arrays.

compareBacktests(baseResult, currentResult)

Use it for: comparing two backtest results stream by stream.
Output: rows with stream, kind, base, current, and delta.
diff = evaluation.compareBacktests( {stats: {A: {type: "numeric", mae: 1.1}}}, {stats: {A: {type: "numeric", mae: 0.8}}} ); // diff[0].delta = -0.3

Interpretation depends on metric direction. For numeric MAE, a lower number is better, so a negative delta means improvement. For categorical accuracy, a higher number is better, so a positive delta means improvement.

scoreDrift(driftReport)

Use it for: extracting the main drift signals into a compact row array.
Input: a discrepancy drift report with a streams array.
Output: rows with stream, kind, score, and flagged.

This is intentionally high-level. It does not preserve every detail from the underlying drift report. It keeps the fields most useful for dashboards, report summaries, or alert checks.

evaluateSystem(system, rows, minTrainSize, windowSize)

Use it for: packaging evaluation inputs for a higher-level workflow.
Current output: {system, rows, minTrainSize, windowSize}.
This function is currently a workflow placeholder. It does not execute a backtest itself in the current implementation. The docs describe the real behavior here so a beginner does not assume it already runs model evaluation.

How To Read The Output

Field How to interpret it
comparisons Total number of streams that were checked.
matches How many streams matched exactly under the module’s rules.
accuracy matches / comparisons. Easy headline metric.
numericMae Average numeric error size. Lower is better.
categoricalAccuracy Label accuracy only. Higher is better.
byStream The detailed row-level evidence behind the summary metrics.

When To Use Which Function

  • Use scoreForecast() when you have one forecast and one actual outcome.
  • Use summarizeBacktest() when you already have backtest stats and need printable rows.
  • Use compareBacktests() when you want to judge whether a revised model improved over a baseline.
  • Use scoreDrift() when you want one compact row per stream from a discrepancy report.
