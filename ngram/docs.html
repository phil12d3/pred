ngram Documentation

Beginner-friendly reference for the ngram module in ns. This guide explains what an n-gram model is, how this implementation trains and generates sequences, what each public function does, and what the returned objects mean.

The goal of this package is simple sequence prediction from observed counts. It does not use neural networks, embeddings, or transformers. It just counts what tends to follow a given context, turns those counts into probabilities, and samples from them.

Import Use pkg = import("./ngram.ns") and then ng = pkg.ngram.

1. What This Module Is For

The ngram module learns short sequence patterns from data. You give it examples of sequences, and it learns which item usually comes next after a context of up to n previous items.

It supports three common modes:

  • Numeric item mode: arrays such as [1, 2, 3, 4]
  • Character mode: strings treated as one character at a time, such as "hello"
  • Token mode: strings split into words/tokens, such as "hello world again"

This makes it useful for small sequence demos, toy predictive systems, simple text generation, next-step prediction, or teaching how probabilistic sequence models work.

Important: This is a local frequency model, not a semantic model. It only knows what followed what in the training data. It does not "understand" meaning.

2. The Basic Idea Behind n-Grams

An n-gram model looks at the last n items of context and asks: what usually came next after this context in the training data?

2.1 Example With Numbers

Training sequences: [1, 2, 3] [1, 2, 4] [1, 2, 3]

If n = 2, then the context [1, 2] is followed by:

  • 3 two times
  • 4 one time

So the predicted next-item distribution becomes:

P(3 | [1,2]) = 2 / 3 P(4 | [1,2]) = 1 / 3

2.2 Example With Text

Training strings: "abba" "abca"

In character mode with n = 2, the context "ab" has been followed by both "b" and "c". So generation from "ab" may continue as either "abba" or "abca", depending on the probability draw.

2.3 What "Order" Means Here

In this package, the order argument means the maximum context length. So:

  • order = 1 means look back up to 1 item
  • order = 2 means look back up to 2 items
  • order = 3 means look back up to 3 items

The model also learns shorter contexts automatically at sequence starts, because the first item has no history, the second item has only one item of history, and so on.

3. What the Module Exposes

The umbrella import exposes one namespace:

pkg = import("./ngram.ns"); ng = pkg.ngram;

Public functions:

ngram.defaultConfig()Returns the base configuration object.
ngram.sequence(value, config)Turns input into a sequence array according to the mode.
ngram.train(data, order, config)Builds a trained model from sequence examples.
ngram.predictNext(model, history, limit)Returns ranked next-item candidates for a history.

ngram.render(sequenceValues, config)Converts a sequence array back into output form, mainly for text modes.

4. Training Data Formats

The module accepts different shapes depending on what you want to model.

4.1 Numeric or General Item Sequences

model = ng.train( [[1, 2, 3], [1, 2, 4], [1, 2, 3]], 2, {unit: "items", addStopToken: false} );

Use unit: "items" when your data is already an array of values and should not be split further.

4.2 Character-Level Text

model = ng.train( ["abba", "abca"], 2, {unit: "chars", stopToken: "<END>"} );

Use unit: "chars" when you want each character to be one item in the sequence.

4.3 Token-Level Text

model = ng.train( ["red blue stop", "red green stop"], 1, {unit: "tokens", stopToken: "stop", separator: " "} );

Use unit: "tokens" when you want strings split into word-like pieces first.

How token mode tokenizes: it splits on common whitespace and punctuation. It is intended to be simple and practical, not linguistically complete.

5. Public Functions

5.1 defaultConfig()

What it does: returns the baseline settings used by the module when you do not override them.

cfg = ng.defaultConfig();

Typical use: inspect available fields, copy them, then override only what you need.

5.2 sequence(value, config)

What it does: normalizes one input into an array sequence.

Why it matters: the model always trains and predicts on arrays internally. This helper defines how strings or arrays become that internal sequence.

ng.sequence("hello", {unit: "chars"}); // ["h", "e", "l", "l", "o"] ng.sequence("hello world", {unit: "tokens"}); // ["hello", "world"] ng.sequence([1, 2, 3], {unit: "items"}); // [1, 2, 3]

Input rules:

  • If the value is already an array, it is copied as-is.
  • If the value is a string and mode is chars, it becomes one character per array element.
  • If the value is a string and mode is tokens, it is tokenized into word-like pieces.
  • If the value is a non-string scalar, it becomes a one-item array.

5.3 train(data, order, config)

What it does: builds a model by counting how often each context is followed by each next item.

model = ng.train( [[1, 2, 3], [1, 2, 4], [1, 2, 3]], 2, {unit: "items", addStopToken: false} );

Important behavior:

  • The model records contexts from length 0 up to the requested order.
  • If a stopToken is configured and addStopToken is enabled, the stop token is appended to training sequences if it is missing.
  • Each context bucket stores counts of possible next values.

Why shorter contexts exist: sequence starts do not have enough history yet, so the model also learns beginnings like:

  • [] -> first item
  • [first] -> second item
  • [first, second] -> third item

5.4 predictNext(model, history, limit)

What it does: returns the observed next-item choices for a given history, ranked by count.

rows = ng.predictNext(model, [1, 2], 5);

What the function tries to do:

  • Convert the history into a sequence array
  • Try the longest suffix context first
  • If that exact context is unknown, back off to a shorter suffix
  • Return candidates with counts and probabilities
Backoff behavior: if the model cannot match the full context, it tries a shorter one. For example, if order is 3 and history is [9,1,2], but only [1,2] is known, the model uses [1,2].

5.5 generate(model, start, options)

What it does: generates one continuation path by repeatedly predicting the next item and sampling from the candidate probabilities.

result = ng.generate(model, "ab", {maxSteps: 5, seed: 7});

Generation loop:

  1. Start from the given sequence
  2. Find next-item candidates from the model
  3. Choose one using the learned probabilities
  4. Append it to history
  5. Stop on stop token, missing transition, or max step count

Stop behavior: if the chosen next value equals the model stop token, generation ends and the stop token is not appended to the visible returned sequence.

5.6 render(sequenceValues, config)

What it does: converts an internal sequence array back into output form.

ng.render(["h", "e", "l", "l", "o"], {unit: "chars"}); // "hello" ng.render(["red", "blue"], {unit: "tokens", separator: " "}); // "red blue" ng.render([1, 2, 3], {unit: "items"}); // [1, 2, 3]

For text modes this is the function that turns arrays back into strings. For item mode it returns an array copy.

6. Config and Option Fields

The module uses the same general config shape for training helpers and generation helpers. Not every field affects every function, but the full set is small and easy to inspect.

Field Default Meaning
order 2 Maximum context length to learn or use. In practice, this is the n in the n-gram style context window.
unit "chars" Input interpretation mode. Allowed values are "chars", "tokens", and "items".
lowercase false If true, text input is lowercased before sequence conversion. Useful when you want "Hello" and "hello" treated as the same item sequence.
separator " " String inserted between items when rendering token-mode output.
stopToken null Special token that ends generation when selected. This can be a word like "stop" or a synthetic marker like "<END>".
addStopToken true If true and a stop token is configured, training sequences get that stop token appended when it is not already present.
seed 42 Deterministic pseudo-random seed used during generation if you do not override it per call.
maxSteps 32 in generate() Maximum number of generation steps before stopping with reason "max_steps".

6.1 Training-Time vs Generation-Time Use

Some fields matter mostly during training:

  • order
  • unit
  • lowercase
  • stopToken
  • addStopToken

Some fields matter mostly during generation:

  • seed
  • maxSteps
  • separator when rendering token-mode text

7. Model Object Properties

train() returns a plain object representing the learned counts and metadata. You can inspect it directly.

{ type: "ngram", order: 2, unit: "items", itemMode: "items", lowercase: false, separator: " ", stopToken: null, addStopToken: false, seed: 42, sequences: 3, observations: 9, transitions: {...}, vocabulary: {...}, vocabularySize: 4, contexts: 6 }
typeFixed string identifying the model kind. Currently "ngram".
orderThe maximum learned context length.
unitThe public mode name used to interpret inputs and outputs.
itemModeInternal normalized copy of the mode. In practice this matches unit.
lowercaseWhether text was normalized to lowercase.
separatorDefault separator for token rendering.
stopTokenThe configured generation stop token, if any.
addStopTokenWhether stop tokens were auto-appended during training.
seedDefault deterministic seed stored with the model.
sequencesHow many non-empty training sequences were used.
observationsTotal context-to-next-item observations recorded.
transitionsMain learned mapping from contexts to next-item count buckets.
vocabularyMap of seen item keys to original values.
vocabularySizeNumber of unique items observed.
contextsNumber of distinct context buckets learned.

7.1 What Is Inside transitions?

Each context key points to a bucket shaped like this:

{ context: [1, 2], total: 3, nextCounts: { "Number:1:3": 2, "Number:1:4": 1 }, nextValues: { "Number:1:3": 3, "Number:1:4": 4 } }

This means the context [1,2] was seen three times in total, with next value 3 twice and 4 once.

8. Prediction and Generation Result Shapes

8.1 predictNext() Rows

predictNext() returns an array of rows like this:

{ value: 3, count: 2, probability: 0.666667, context: [1, 2], order: 2 }

Field meanings:

valueThe candidate next item.
countHow many times this item followed the matched context.
probabilitycount / total within the matched context bucket.
contextThe actual context that matched after any needed backoff.
orderThe matched context length used for this prediction.

8.2 generate() Result

generate() returns one object with the generated sequence plus step-by-step metadata.

{ sequence: ["a", "b", "c", "a"], rendered: "abca", terminated: true, reason: "stop_token", seed: 642666333, steps: [ {context: ["a","b"], order: 2, value: "c", probability: 0.5}, {context: ["b","c"], order: 2, value: "a", probability: 1} ] }

Main fields:

sequenceThe generated visible sequence values. Stop token values are not appended here.
renderedRendered output form. String for text modes, array for item mode.
terminatedTrue only when generation stopped because the configured stop token was selected.
reasonWhy generation stopped. One of "stop_token", "no_transition", or "max_steps".
seedThe updated pseudo-random seed after generation finished.
stepsPer-step log of chosen values and matched contexts.

9. Internal Behavior: Counting, Backoff, and Sampling

9.1 Counting During Training

For each position in a training sequence, the model records one observation:

context -> next_value

Suppose the sequence is:

[1, 2, 3]

With order = 2, the observations are:

  • [] -> 1
  • [1] -> 2
  • [1,2] -> 3

If a stop token is auto-appended, there is one more observation:

  • [2,3] -> stopToken

9.2 Backoff During Prediction

The model tries to match the longest possible suffix of the provided history.

history = [9, 1, 2] order = 3

It will try contexts in this order:

  • [9,1,2]
  • [1,2]
  • [2]
  • []

This is useful because generation would otherwise stop too early whenever the exact longest context was unseen.

9.3 Probability Calculation

Inside one matched context bucket, probabilities are simple empirical frequencies:

probability(next) = count(next after context) / total observations for that context

No smoothing is currently applied. That means an unseen continuation has probability 0.

9.4 Sampling During Generation

The package uses a small deterministic pseudo-random generator. Given the same seed and model, generation is reproducible.

Sampling works like this:

  • Build the candidate rows and their probabilities
  • Draw one random number between 0 and 1
  • Walk through the cumulative probability mass
  • Pick the row where the random number lands
Why deterministic randomness? It makes examples, tests, and debugging repeatable. If you use the same seed, you get the same generated path.

10. Worked Examples

10.1 Next Number Prediction

pkg = import("./ngram.ns"); ng = pkg.ngram; model = ng.train( [[1, 2, 3], [1, 2, 4], [1, 2, 3]], 2, {unit: "items", addStopToken: false} ); rows = ng.predictNext(model, [1, 2], 5); printline(rows[0].value); // 3 printline(rows[0].probability); // 0.666667 roughly

10.2 Character Generation

charModel = ng.train( ["abba", "abca"], 2, {unit: "chars", stopToken: "<END>", seed: 7} ); result = ng.generate(charModel, "ab", {maxSteps: 5, seed: 7}); printline(result.rendered); // "abba" or "abca" depending on path

10.3 Token Generation

tokenModel = ng.train( ["the cat sat stop", "the cat slept stop", "the dog ran stop"], 1, {unit: "tokens", stopToken: "stop", separator: " "} ); result = ng.generate(tokenModel, "the cat", {maxSteps: 4, seed: 9}); printline(result.rendered); // for example: "the cat slept"

10.4 Lowercasing Text

model = ng.train( ["Hello world", "hello there"], 1, {unit: "tokens", lowercase: true} );

This causes Hello and hello to be treated as the same token.

10.5 Inspecting the Learned Next Choices

model = ng.train( [[10, 20, 30], [10, 20, 40], [10, 20, 30], [10, 50, 60]], 2, {unit: "items", addStopToken: false} ); rows = ng.predictNext(model, [10, 20], 10); for (i = 0; i < rows.count(); i = i + 1) { row = rows[i]; printline("next=", row.value, " count=", row.count, " p=", row.probability, " context=", stringify(row.context), " order=", row.order); }

This is a good first debugging pattern. It shows exactly what the model thinks can come next, how often each continuation was seen, and which context length actually matched.

10.6 Backoff to a Shorter Known Context

model = ng.train( [[1, 2, 3], [1, 2, 4]], 3, {unit: "items", addStopToken: false} ); rows = ng.predictNext(model, [9, 1, 2], 5); printline("matched order = ", rows[0].order); printline("matched context = ", stringify(rows[0].context)); printline("top next = ", rows[0].value);

Even though the full history is [9,1,2], the model may only know the suffix [1,2]. In that case it backs off and still returns a useful answer instead of failing immediately.

10.7 Numeric Generation With a Stop Value

model = ng.train( [ [2, 4, 6, -1], [2, 4, 8, -1], [2, 5, 7, -1] ], 2, {unit: "items", stopToken: -1, addStopToken: false, seed: 12} ); result = ng.generate(model, [2], {maxSteps: 6, seed: 12}); printline("sequence = ", stringify(result.sequence)); printline("reason = ", result.reason); printline("terminated = ", result.terminated);

This shows that stop tokens do not need to be strings. A numeric sentinel like -1 can mark sequence termination too.

10.8 Token Prediction for Phrase Completion

model = ng.train( [ "machine learning model stop", "machine learning pipeline stop", "machine learning model stop" ], 2, {unit: "tokens", stopToken: "stop", separator: " "} ); rows = ng.predictNext(model, "machine learning", 5); for (i = 0; i < rows.count(); i = i + 1) { printline(rows[i].value, " -> ", rows[i].probability); }

This pattern is useful when you do not want full generation yet. You just want to inspect the model’s ranked next-word suggestions after a phrase.

10.9 Reading Generation Steps

model = ng.train( ["abba", "abca"], 2, {unit: "chars", stopToken: "<END>", seed: 7} ); result = ng.generate(model, "ab", {maxSteps: 5, seed: 7}); for (i = 0; i < result.steps.count(); i = i + 1) { step = result.steps[i]; printline("step ", i, " context=", stringify(step.context), " order=", step.order, " chose=", step.value, " p=", step.probability); }

The steps array is useful when you want to explain why a generated sequence took a particular path.

10.10 Generating Until No Transition Exists

model = ng.train( [[1, 2, 3]], 2, {unit: "items", addStopToken: false} ); result = ng.generate(model, [1, 2], {maxSteps: 10, seed: 3}); printline("sequence = ", stringify(result.sequence)); printline("reason = ", result.reason); // likely "no_transition"

If there is no stop token and no further continuation is known, generation ends with reason "no_transition".

10.11 Using sequence() and render() Directly

chars = ng.sequence("Nova", {unit: "chars"}); tokens = ng.sequence("Nova learns fast", {unit: "tokens"}); printline(stringify(chars)); printline(stringify(tokens)); printline(ng.render(chars, {unit: "chars"})); printline(ng.render(tokens, {unit: "tokens", separator: " "}));

These helpers are useful when you want to inspect exactly how the module sees your inputs before training.

10.12 Starting From an Empty Sequence

model = ng.train( [ "red blue stop", "red green stop", "blue yellow stop" ], 1, {unit: "tokens", stopToken: "stop", separator: " "} ); result = ng.generate(model, "", {maxSteps: 4, seed: 4}); printline(result.rendered);

Because the model learns empty-context starts too, generation can begin from nothing. In effect, it asks: "what items usually begin sequences in this training set?"

11. Practical Advice and Caveats

11.1 Choosing the Order

  • Use smaller orders like 1 or 2 when training data is limited.
  • Use larger orders when you want more local structure and have enough repeated data.
  • If order is too large relative to the data, exact contexts become sparse and the model falls back often.

11.2 Stop Tokens

  • Use a stop token when you want generation to know where sequences end.
  • For text, a synthetic token like "<END>" is often convenient in char mode.
  • For token mode, a word like "stop" works if it is not confused with regular content.

11.3 No Smoothing

This implementation does not invent probability mass for unseen next items. If the model never saw a continuation, it cannot predict it. That keeps the behavior simple and transparent.

11.4 Tokenization Is Simple

The token-mode splitter is intentionally lightweight. It is useful for small demos and straightforward corpora, but it is not a full natural-language tokenizer.

11.5 What This Model Cannot Do

  • It cannot reason about long-range meaning.
  • It cannot generalize beyond observed local patterns the way large language models do.
  • It cannot invent new structure except by recombining seen local transitions.
Best mental model: this package is a compact, inspectable sequence memory. It remembers what followed what, and then plays those probabilities back during prediction and generation.
