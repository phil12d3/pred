FFT Documentation

Reference for the standalone FFT module for ns. This module covers complex-number helpers, radix-2 fast Fourier transforms, inverse transforms, and spectrum inspection for real signals.

The emphasis is on direct, inspectable outputs. You give the module numbers, it gives you explicit complex bins, magnitudes, powers, and reconstructed samples without hiding the intermediate shapes.

1) What FFT Is For

The FFT module turns time-domain sequences into frequency-domain bins. This is useful when you want to inspect periodic structure, measure spectral energy, or reconstruct a signal after a transform.

  • Use fftReal() when your samples are ordinary real numbers.
  • Use fftComplex() when your input is already complex.
  • Use ifftComplex() or ifftReal() to reconstruct the input domain.
  • Use spectrum() and dominantBin() for quick inspection.

Typical use cases:

  • Check whether a repeating pattern exists in a short signal.
  • Compare how concentrated two signals are in the frequency domain.
  • Pad a short signal before transforming it, then inspect how the bin layout changes.
  • Round-trip a transform to verify reconstruction quality.
Implementation note: power-of-two lengths use a recursive Cooley-Tukey FFT. Other lengths fall back to a direct DFT so the API still works for arbitrary input sizes.

2) Import And Layout

fft = import("./FFT.ns"); signal = [0, 1, 0, -1, 0, 1, 0, -1]; bins = fft.core.fftReal(signal); printline(bins[0].re);
FFT.ns
Umbrella import that exposes the core namespace.
core.*
Complex-number helpers, FFT functions, inverse transforms, and spectrum utilities.
Module style: the public surface is intentionally small. Most workflows can be expressed with fftReal(), ifftReal(), spectrum(), and dominantBin(), while the complex helpers are there when you want to inspect or manipulate bins directly.

complex row

4) Core Functions

core.complex(re, im)

Create a complex value.

z = fft.core.complex(3, -2);

core.add(a, b), core.sub(a, b), core.mul(a, b), core.scale(a, factor), core.conjugate(a)

Basic complex arithmetic helpers. These are useful when you want to work with bins directly.

a = fft.core.complex(2, 3); b = fft.core.complex(4, -1); product = fft.core.mul(a, b); // { re: 11, im: 10 }

core.magnitude(a) and core.phase(a)

Return the Euclidean magnitude and polar phase of a complex value.

Interpretation: magnitude tells you how much energy is in a bin, while phase tells you its angular orientation. Most quick inspection workflows care about magnitude first.

core.isPowerOfTwo(n) and core.nextPowerOfTwo(n)

Utility functions for sequence sizing. These are useful when you want to explicitly pad a signal before transforming it.

fft.core.isPowerOfTwo(8); // true fft.core.isPowerOfTwo(6); // false fft.core.nextPowerOfTwo(6); // 8

core.padReal(values, size)

Pad a real-valued sequence with trailing zeros up to a requested size, or to the next power of two when size is omitted.

signal = [1, 2, 3, 4, 5]; padded = fft.core.padReal(signal); // [1, 2, 3, 4, 5, 0, 0, 0]
Why pad? Padding does not add new information, but it lets you use the radix-2 FFT path and gives you a denser bin layout to inspect.

core.fromReal(values)

Convert a list of real numbers into complex rows with zero imaginary part.

rows = fft.core.fromReal([3, 1]); // [{re:3, im:0}, {re:1, im:0}]

core.fftComplex(values)

Compute the forward Fourier transform of a complex sequence.

Power-of-two lengths use FFT. Non-power-of-two lengths use DFT fallback.

Performance note: power-of-two sizes are the fast path. Arbitrary lengths still work, but they use the direct DFT implementation and are much more expensive for large inputs.

core.fftReal(values)

Convenience wrapper for real-valued sequences.

bins = fft.core.fftReal([1, 0, 0, 0]); for (i = 0; i < bins.count(); i = i + 1) { printline(i, " => re=", bins[i].re, " im=", bins[i].im); }

core.ifftComplex(values)

Compute the inverse transform and return complex rows.

Use it when: your bins are complex and you want the full complex-valued reconstructed signal, not just the real part.

core.ifftReal(values)

Inverse transform for signals that were originally real. Returns the real part of each reconstructed sample.

signal = [0, 1, 0, -1, 0, 1, 0, -1]; reconstructed = fft.core.ifftReal(fft.core.fftReal(signal));
Practical expectation: reconstructed values should be very close to the originals, but tiny floating-point residues are normal.

core.magnitudes(values)

Map a list of complex bins to a list of magnitudes only.

mags = fft.core.magnitudes(fft.core.fftReal([1, 0, 0, 0]));

core.spectrum(values)

Compute a real-signal transform and return rich spectrum rows for each bin.

spec = fft.core.spectrum([0, 1, 0, -1, 0, 1, 0, -1]); for (i = 0; i < spec.count(); i = i + 1) { printline(spec[i].index, " => ", spec[i].magnitude); }

When spectrum() is better than fftReal(): use it when you want a report-like structure with index, magnitude, and power already attached instead of manually deriving those from complex bins.

core.dominantBin(values)

Return the spectrum row with the largest magnitude.

Interpretation note: for many real periodic signals, you will often see mirrored peaks at symmetric bins. dominantBin() returns one of them, not both.
dominant = fft.core.dominantBin([0, 1, 0, -1, 0, 1, 0, -1]); printline(dominant.index, " ", dominant.magnitude);

5) End-To-End Patterns

Impulse Response

signal = [1, 0, 0, 0]; bins = fft.core.fftReal(signal); // Every bin should be {re:1, im:0}

Simple Periodic Signal

signal = [0, 1, 0, -1, 0, 1, 0, -1]; dominant = fft.core.dominantBin(signal); printline("bin=", dominant.index, " mag=", dominant.magnitude);

Reconstruction

signal = [1, 2, 3, 4, 5]; reconstructed = fft.core.ifftReal(fft.core.fftReal(signal));

Padding Before Transforming

signal = [1, 2, 3, 4, 5]; padded = fft.core.padReal(signal); spec = fft.core.spectrum(padded);

Comparing Two Signals

a = [0, 1, 0, -1, 0, 1, 0, -1]; b = [1, 1, 1, 1, 0, 0, 0, 0]; domA = fft.core.dominantBin(a); domB = fft.core.dominantBin(b); printline("A => ", domA.index, " / ", domA.magnitude); printline("B => ", domB.index, " / ", domB.magnitude);

Inspecting Complex Bins Directly

bins = fft.core.fftReal([0, 1, 0, -1]); for (i = 0; i < bins.count(); i = i + 1) { phase = fft.core.phase(bins[i]); printline(i, " re=", bins[i].re, " im=", bins[i].im, " phase=", phase); }

6) Interpretation Notes

  • The output bins are ordered by frequency index, not by magnitude. If you want the strongest frequency component, use dominantBin() or sort the spectrum yourself.
  • Real-valued signals often produce mirrored frequency components. This is expected and not a bug.
  • Very small non-zero values such as 2.44929e-16 are normal floating-point artifacts.
  • Padding with zeros changes the transform resolution and layout, but does not create new signal content.
  • For non-power-of-two input lengths, the module keeps the API behavior identical, but uses the slower DFT fallback internally.
